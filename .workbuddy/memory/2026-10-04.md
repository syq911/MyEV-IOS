## 交接接手 + 交付链路（Actions 编译）首次打通

**背景**：接手 MyEV-IOS（EhViewer 定制版 iOS）。本沙箱为 Windows，`xcodebuild` 不可用，
唯一验证途径是「推送 → GitHub Actions」。本次目标：验证这条链路端到端可用。

**仓库现状**（核实）：
- 分支 `fix/1.4.15`，HEAD `28a760f`，与 `origin/fix/1.4.15` 一致；工作区干净。
- `v1.4.15` 的 Actions 运行三个 job 全绿：`build-ipa` / `test` / `release`；
  Release 产物含 `EhViewer.ipa` + `source.json`。
- `.github/workflows/deploy_ios.yml` 持续失败属已知情况（缺 Apple 签名密钥），与本项目发布无关。

**本次做的验证**：
1. 从 `fix/1.4.15` 建一次性烟雾分支 `ci/smoke-2026-10-04`（空提交 `f07df7d`）并推送。
2. 触发 run `37212049300`：`build-ipa` ✅ + `test` ✅，产物 `EhViewer-ipa-58`（4.05 MB）；
   `release` 按预期 skipped（非 tag）。
3. 测试日志核实：**50 tests / 4 suites 全通过**，含金标准 OCR 测试
   `ocrMatchesGoldenFixture()`（13.3s）与 `ocrRecoversMostLinesOnDensePage()`（17.6s）。
4. 清理：远端分支用 API 删除，本地分支 `-D`，并 `git remote prune origin`。

**踩到的坑（重要）**：
- 仓库级 `credential.helper` 为 `helper-selector`（Git Credential Manager 的交互式选择器），
  它排在 helper 列表最前，凭证缓存失效时会**弹窗阻塞**，导致 `git push`（尤其 `--delete`）被挂死
  （表现为 SIGTERM、无输出）。
- **正确姿势**：先清空 helper 列表再挂 store，即
  `git -c credential.helper= -c credential.helper='store --file=/tmp/.ggcred' push ...`
  实测 2.3s 返回，稳定。
- 托管 Python 看不到 Git Bash 的 `/tmp`，跨进程传 token 要用环境变量而不是读 `/tmp/.ggcred`。

**环境处理**：
- 仓库里 `distribute_mac.sh` 显示「M 已修改」只是 Windows 无法表达可执行位（755→644），
  非真实改动。已用 `git config core.fileMode false` 消除该噪音（仅本地 `.git/config`，不影响他人）。

**未做**：未改任何业务代码，未打 tag、未发 Release。

## 变现方向调研（联网 + 本地核查）

产出报告：`D:/Code/MyEV-IOS/MyEV-IOS-变现路径综合建议.md`（**在仓库外**，勿提交进 public 仓库）。

关键结论（长期有效）：
- **许可证**：上游 EhViewer-Apple 与本地 LICENSE 均为 **Apache-2.0**，Swift 独立实现、无 GPL 混入
  → 闭源/商用合法可行；但 Apache 不授商标，"EhViewer"名称勿用于收费场景。
- **策略结论**：客户端保持开源（public 仓库 + 免费 Actions = 零成本最优），付费价值服务端化；
  推荐 open-core（客户端开源 + 服务端闭源）。
- **构建方案**：无 Mac 现状即最优；要私有仓库 → 自托管 runner 免费（二手 M1 Mac mini 闲鱼
  ¥1800–2600，或 MacinCloud $25–29/月）；Xcode Cloud 随 $99/年开发者账号含 25h/月。
- **支付红线**：Paddle/Lemon Squeezy/Dodo/Polar 全部明文禁成人内容 → 付费产品必须定位为
  独立"AI 漫画翻译云服务"，与 EH 品牌/客户端解耦；收款倾向 Lemon Squeezy（个人可入驻）。
- **法律红线（国内）**：刑法 363 条，有三亚判例（爱发电引流、获利 805 元即刑拘）；爱发电平台
  本身被罚过 → **国内渠道绝不为 EH 内容访问收费**；服务端不缓存/转发任何图片内容。
- **先例**：Tachimanga（闭源+订阅 $1.99/$9.99/$24.99）、Yomu（闭源+Premium+AI 翻译）为商店版
  路线模板；Hot Tub 先例证明成人 App 可过苹果公证走 EU AltStore PAL。
- **成本模型**：DeepSeek V4-Flash 每页翻译 ≈ $0.0002–0.0004，Pro $2.99/月毛利率 >85%。
- **代码隐患**：`MangaTranslationSettings.swift:168` 默认模型 `deepseek-chat` 别名已于
  2026-07-24 被官方弃用 → 下版本应改默认值为 `deepseek-v4-flash`。

## 变现报告增补：解耦追问（已写入报告 4.3.1）

用户追问"EH 和翻译在同一 App 里怎么解耦"。核心答案（四层切割法，报告 4.3.1）：
法律评价的是"钱与淫秽内容有无对价 + 是否控制内容传播"（快播案三要素：明知/控制/牟利），
不是功能是否在同一二进制。四层：① 对价切割（不付费 App 100% 可用）② 数据切割
（服务端只过文本不碰图片）③ 品牌切割（SaaS 独立 + 必须有独立 Web 端证明实质合法用途）
④ 资金流切割（官网收款、App 内无收银台）。落地关键：现有 baseURL+apiKey 自定义端点
天然支持，云服务 = 托管版 OpenAI 兼容端点，App 改动极小。

## 通用阅读器方向调研（第二份报告）

产出：`D:/Code/MyEV-IOS/MyEV-IOS-通用阅读器源生态调研与技术方案.md`（仓库外）。
核心结论：
- **Legado（开源阅读）案 2026-01 上海闵行：开发者判刑 2 年**——"通用阅读器+用户导入书源"
  不能自动免责；定罪三支柱：自己传播书源（公众号/QQ群）+ 运营 200 万粉社群主导生态 +
  变现超百万。书源被定性"预设抓取规则的深度链接指令包"。**安全靠"三不"：不碰源、
  不碰国内传播/社群、不碰内容对价变现**。
- Tachiyomi 死因 = 官方维护扩展列表（Kakao C&D）→ App 必须出厂零源、零官方推荐。
- keiyoushi 400+ 源活跃但 **2026 年 DMCA 移除全部成人源（含 EH）**；EH 源现于个人仓库
  （xixiwan/mihon-ehentai-extension，Mihon/Tachimanga 通用）。
- 技术选型定调：**JavaScriptCore + 单文件 JS 源（Venera 模式）**；源 API 契约照 Tachiyomi
  七方法模型；勿碰 Tachiyomi APK 兼容；Cloudflare 用隐藏 WKWebView 兜底。
- App Store 先例：Tachimanga / Yomu 均支持用户自填 Tachiyomi 仓库 URL 且在架。
- 下一步候选：① 源契约正式文档 ② 现有代码泛化改造点盘点 ③ fix/1.4.16 修 deepseek-chat 默认模型。
