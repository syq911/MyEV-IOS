- `RemoteReadingSource` 归档优先：有归档的章节**页列表不问脚本**、**页图不发请求**。
- `DownloadCoordinator`（App 层）：批量入队、跳过已下载、暂停/继续/取消/重试、
  完成后后台打包归档。

### M3-2 下载界面（77151dc）
- `DownloadsView`：进行中（进度/控制）+ 已下载（按作品分组、体积、点进去离线阅读、
  导出 CBZ、删除、二次确认）+ 已结束（失败原因、重试）。
- 作品详情：工具栏「下载全部」+ 章节行左滑「下载本话 / 删除下载」。
  单话下载**不放行内**（行本身是 NavigationLink，塞按钮会误触）。

### M3-3 自建服务器（fd81dff）
- `AppCore.MangaDataSource` 统一接口 + `MangaDataSourceProviding` / `Probing`；
  浏览/详情/章节/阅读/下载全部只认它，界面里再没有「脚本源还是服务器」的分支。
- `HostedServer` + `ServerStore`：标识由名称派生（同名加序号、超长截断）；
  配置目录标记不参与 iCloud 备份；文件损坏改名备份后当空处理。
- `KomgaDataSource` / `KavitaDataSource`：宽容解析（JSONSerialization + Mapping
  取值助手，不用 Codable——自建服务器的字段类型在版本间会变）；映射写成纯函数可单测。
  Kavita 先换 JWT、401 换一次重试；图片走查询串鉴权，故错误文案必须脱敏（`LogRedaction`）。
  Komga 页地址用接口返回的 `number` 拼（页码基准在版本间变过，不能猜）。
- `CompositeDataSourceProvider` **显式先判断归属再调用**——靠 try/catch 挨个试会让
  「服务器地址填错」显示成「源未安装」，排查方向跑偏。

### M3-4 登录与人工验证（3053f87）
- `SourceLoginView`：WKWebView + `WKWebsiteDataStore.nonPersistent()`（网页会话与
  App 网络栈、其他来源完全隔离）；不自动判断登录成功（真实站点上不可靠）。
- `CookieHarvest`：按主机过滤（同域/子域/空域收，第三方域丢）、丢过期与无名项、
  同名去重；写入前清空该来源容器，但**本次 0 条时不清理**；域归一化去前导点
  （留着 `.Example.com` 会让后缀匹配永远失败 → 「登录了但请求不带 Cookie」）。
- `ChallengeDetector`：只看 403/429/503 **且**正文有厂商标记。只看状态码会把所有 503
  当验证页；不看状态码会让页脚写着「Powered by Cloudflare」的正常站点被误伤。

### M3 收尾：后台执行断言（3686fd1）
- `BackgroundExecutionKeeper`：驱动循环外圈 `beginBackgroundTask` / 归还。
  不用 URLSession 后台传输（下载含 JS 沙箱与打包，交不了给系统进程）。
  必须归还（不还调 `endBackgroundTask` 会被强杀，已抓的页连同散图一起丢）；
  文案不吹（说「可以离开这一页」，不说「关掉 App 也会继续」）。

### CI 迭代（本阶段共 6 轮，暴露 4 个真实缺陷）
1. **`FilePageStore` 拒绝含 `/` 的 jobID → 在线章节全下不了**（run 50，28 条断言）。
   章节主键是 `<mangaID>|<url>`，必然含 `/`。抽出 `FileNameSanitizer`，
   归档与散图共用同一套命名。
2. **终结态任务记录永久挡住重新下载**（同轮）。加 `DownloadQueue.remove(_:)`，
   入队与重试都先摘掉旧记录。
3. **`Date.ISO8601FormatStyle.year()`** 是在类型上调实例方法（run 52，两个作业一起红）。
4. **`RuntimeDataSource` 够到池的 private `store`**（run 53/54）。改为池暴露
   `isInstalled(_:)`，而不是把 store 放开。

### 本轮修掉的两个**真实缺陷**（都是测试抓出来的）
1. `CookieJar.set(_:for:)` 返回的是**被拒绝的条数**，不是写入条数。
   我把它当写入条数 → 收割成功也返回 0 → 界面显示「没有找到可保存的登录凭据」，
   而 Cookie 其实已经存进去了。改成 `stored.count - rejected`；
   并把「宿主存不下的 Cookie」（名称含 `;` `=` 换行、值含换行）在过滤阶段就拒掉，
   这样「收下的一定写得进去」，「清空旧凭据再写入」不会白做。
2. 删除归档与「正在完成的下载」竞态：`download()` 会顺带启动驱动，而驱动与
   测试/界面的推进是并发的，于是「刚删完又被写回来」。
   实现侧：删除前先取消该作品尚未终结的任务；
   测试侧：新增 `settle()`（先 `waitUntilSettled` 再 `drain`），19 处统一替换。

### 另一类教训：测试期望写错，而不是实现错
`cdn.example.com` 的 Cookie 拿去比 `www.example.com` —— 两者是**兄弟域**，
本来就不该收。修的是测试，并另补一条「兄弟域不收」把语义钉住。
